## CPU 작업과 I/O 작업

CPU 작업은 사용 가능한 CPU 병렬성 근처에서 시작해 측정합니다.
I/O 대기가 많으면 더 많은 워커가 도움이 될 수 있지만, 아래 식은 초기 사고 모델입니다.

```text
스레드 수 ≈ CPU 수 × 목표 CPU 이용률 × (1 + 대기 시간 / 계산 시간)
```

이 식에는 연결 풀 상한, 외부 서비스 처리 능력, 메모리, rate limit이 반영되지 않습니다.
06 예제는 CPU 벤치마크가 아니라 자원 상한과 대기 구간을 관찰하는 실험입니다.

## 연결 개수와 점유 시간

작업 하나가 각 자원을 한 번 사용한다고 가정하면 자원별 처리 능력의 거친 상한을 비교할 수 있습니다.

| 자원 | 개수 | 작업당 점유 시간 | 이상적 처리 능력 |
| --- | --- | --- | --- |
| 워커 | 40 | 550ms | 약 73건/초 |
| DB | 10 | 50ms | 약 200건/초 |
| HTTP | 20 | 500ms | 약 40건/초 |

이 가정에서는 HTTP 쪽이 먼저 제한됩니다. 실제 워커 점유 시간에는 연결 획득 대기도 포함되어 처리량은 더 낮아질 수 있습니다.
HTTP 대기 내내 DB 연결까지 보유하면 DB 점유 시간이 약 550ms로 늘고, DB의 상한은 약 18건/초로 줄어듭니다.
단순히 여러 풀의 개수 중 최솟값만 비교해서는 이 차이를 설명할 수 없습니다.

Little's Law `L = λ × W`에서 W는 선택한 시스템 경계 안의 평균 체류 시간입니다.
큐 대기를 포함한 전체 시스템의 L을 바로 필요한 워커 수로 해석하지 않습니다.
안정 상태의 평균 관계이며, 용량 설계에는 피크·지연 분포·실패·재시도도 고려해야 합니다.
