## 문서를 둘 위치

- 언어 문법·여러 모듈에서 쓰는 Kotlin 패턴: `docs/kotlin/`
- 동시성·스레드 풀 등 학습 주제의 원리: 해당 모듈의 `docs/`
- 실행 방법·읽는 순서·관련 문서: 각 모듈의 README
- 공통 API 계약과 제약: `study-support/README.md`
- 모듈 책임과 의존 방향: `docs/architecture.md`

같은 설명의 본문은 한 곳에서 관리합니다. 다른 모듈에서는 복사 대신 링크합니다.
문법 문서에서 실제 예제로, 모듈 문서에서 문법 문서로 양방향으로 연결합니다.

## 학습 내용을 추가하는 형식

파일명은 `Ex05.md`보다 `choosing-an-executor.md`처럼 개념을 표현합니다.
새로운 질문이 기존 주제에 속하면 기존 문서에 절을 추가하고, 독립적으로 찾아볼 질문이면 파일을 나눕니다.

```markdown
# 질문 또는 개념

## 헷갈렸던 점
Java에서의 예상과 Kotlin 코드의 차이를 적는다.

## 핵심 설명
왜 이렇게 동작하는지 짧게 설명한다.

## 실수하기 쉬운 코드와 권장 코드
최소 코드, 예상 결과, 바꾸는 이유를 나란히 적는다.

## 적용 범위
언제 유용하고 어떤 전제에서는 다른 선택이 필요한지 적는다.

## 실제 예제와 근거
레포 코드 링크와 확인한 공식 문서 링크를 적는다.
```

문법 사전이나 실험 기록은 모든 제목을 기계적으로 따를 필요가 없습니다.
질문은 남기되 대화의 인사말·추가 작업 제안은 정리합니다. 답이 불확실하면 `확인 필요`와 확인할 조건을 적습니다.

## 갱신할 때 확인할 것

1. 코드 전체를 복사하지 않고 설명에 필요한 부분만 발췌한다. 의사 코드·실패 예제는 표시한다.
2. 줄 번호 대신 파일 링크와 함수명을 사용한다. 이동 시 역방향 링크도 고친다.
3. 특정 실행 로그는 관찰 예시로 표시한다. 실행 시간·스레드 순서를 API 보장처럼 설명하지 않는다.
4. 권장 패턴에는 적용 조건을 적고, 버전 의존 설명에는 Kotlin/JDK 기준과 공식 출처를 남긴다.
5. 새 문서는 이 지도 또는 모듈 README에서 도달할 수 있게 연결한다.

이번 정리 기준은 [버전 카탈로그](../gradle/libs.versions.toml)의 Kotlin 2.4.0과 JDK 25입니다.
이동 전 문서 이름은 Git 이력에서 확인할 수 있습니다. 본문을 중복 보관하는 별도 아카이브는 만들지 않습니다.
